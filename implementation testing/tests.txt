## Implementation Testing

### 1. Overview
Attendly was tested using a combination of **automated tests** (unit and UI tests) and **manual functional testing**. The goal was to verify that attendance calculations are accurate, all features work as expected, and user data persists correctly.

### 2. Testing Tools
| Tool | Purpose |
|------|---------|
| Vitest | Test runner |
| React Testing Library | Rendering components and simulating user actions |
| @testing-library/user-event | Simulating typing and clicking |
| jsdom | Browser-like environment for tests |

### 3. How to Run the Tests
```bash
# install dependencies
npm install

# run all tests
npm test
```

### 6. Sample Calculation (Verification)
- Attended = 7, Conducted = 10, Target = 75%
- Attendance = 7 / 10 = **70%** (below target)
- Lectures needed = ceil((0.75 × 10 − 7) / (1 − 0.75)) = **2**
- App output: "need to attend 2 lectures" ✅

### 8. Known Limitations
- Passwords are stored in plain text in localStorage (no backend or hashing).
- The "Active Students" count is based on seeded demo users, not live data.
- Data is limited to one browser/device (no cloud sync).
- No validation for overlapping classes in the timetable.

### 9. Future Improvements
- Add a backend with secure authentication (password hashing).
- Add more automated tests (Today tab, Calendar, Subjects).
- Add end-to-end tests using Cypress or Playwright.
- Set up CI (GitHub Actions) to run tests on every push.
